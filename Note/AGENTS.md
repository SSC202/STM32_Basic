# Note 文档格式审查与修复

本文件适用于 `Note` 目录及其子目录。执行文档格式审查时，充当文档格式审查与修复 agent；审查范围由用户指定，未指定时仅处理当前任务涉及的 Markdown 文档，不自行扫描或修改整个目录。只操作 `Note` 内的文件；不得通过相对路径、符号链接或联接点越过该边界。更深层目录中的 `AGENTS.md` 和用户的具体要求优先于本文件。

## 基准和原则

中文技术文档应使用清晰的标题、段落、列表、引用、表格、图片和 LaTeX 公式；标题和段落之间通常留空行；图片优先使用相对于文档的路径。遵循下述审查标准，同时尊重已有文档中合理的格式差异。

只处理格式，保留原文含义、技术数据、公式和示例。优先保留当前文档已有的合理风格；有歧义或可能改变渲染、引用目标、含义时，不自动修改，记录位置和原因。只编辑用户指定范围内需要修复的文件，不覆盖用户已有改动。保持原有文本编码、BOM 和换行风格。

## 格式审查标准

1. **标题**：使用 `# 标题` 形式，标记与标题文字之间留一个空格；通常一个文档使用一个一级标题。二级标题可采用 `## 1. 标题`；三级标题不使用数字编号，直接写标题文字。其他标题编号和层级以当前文档的结构为准。检查标题跳级、编号不连续和重复一级标题；结构或编号的语义不明确时只报告，不自行调整。
2. **段落与分隔**：普通段落之间保留一个空行；标题、独立图片、表格和水平分隔线 `---` 前后按 Markdown 结构保留必要空行。删除普通正文中无意义的行尾空格和多余空行；保留 Markdown 硬换行、代码块、表格单元格以及其他有意义的空白。非空文件末尾保留一个换行。
3. **列表与引用**：无序列表优先沿用文档已有标记，参考文档常用 `- `；有序列表使用数字加句点。标记后留空格，同级缩进保持一致。调整缩进前，结合标题、上下文、步骤顺序及内容含义，判断某个总项或步骤之后的哪些段落、子列表、图片、引用和代码属于同一逻辑单元，直到遇到同级或上级内容；将属于该项的内容按 Markdown 语法归入该项，避免仅凭相邻位置或现有缩进判断。归属不明确时保留原样并报告。列表项作为标题或总项时，其子点应缩进并归属于该项；列表项内的图片与该项的文本内容保持相同缩进，引用内也须保留引用前缀；在引用中保留 `>` 前缀，再按父列表项的内容起始位置缩进子列表，确保 Markdown 正确解析为嵌套列表。引用使用 `>`，引用内的列表、段落、图片和公式保持其引用层级与缩进，不改变列表的从属关系。
4. **图片与链接**：文档使用的本地图片应存放在文档所在目录的 `assets` 文件夹中，并使用相对于文档的路径引用。检查本地图片和链接的目标是否存在；URL、锚点、查询参数和相对路径分别处理。保留已有图片替代文本，不要求统一成 `NULL`。整理图片时，先确认引用目标和其他引用关系，避免同名文件覆盖；仅在目标唯一、可验证且修改后仍位于 `Note` 内时移动图片并同步更新受影响的引用，必要时重排图片编号。存在歧义、冲突或无法安全更新全部引用时保留原样并报告。除整理图片所需操作外，不移动或重命名文档及资源。
5. **公式**：保留行内 `$...$`、独立 `$$` 公式及其 LaTeX 内容；独立公式的分隔符和内容保持原有结构。引用和列表内的公式尤其要保留 `>` 前缀与必要缩进。不得修改变量、上下标、单位、运算符或公式内容，也不为了统一空行而改变公式渲染。
6. **代码**：保留代码内容、缩进和围栏字符；仅在语言能从代码和上下文明确判断时，为缺少语言标识的围栏代码块添加标识，无法判断则报告。不要把命令输出、示意图或普通文本猜测成代码语言。兼顾 Typora 与常见网页 Markdown 渲染器：涉及列表、引用和代码块的复杂嵌套时，优先使用顶层围栏代码块和相邻的步骤说明，避免代码块被误解析；调整时保留步骤关系和代码原文。
7. **表格**：使用 Markdown 表头和分隔行，保持列数、单元格内容、对齐标记和转义字符。根据表格与周围步骤、列表的逻辑归属调整整体缩进，使表格与所属项的其他内容对齐；当 `>` 引用块内只有该表格时，移除表格整体的引用前缀；如果引用块还包含说明、列表或其他内容，则保留引用关系，不单独移除表格的 `>` 前缀。单元格内的文本遵循正文中的中英文、标点、引号、文件名和代码标识符等规范，同时保留表格语法、链接、代码、公式及其他有固定写法的内容。仅在不影响解析和含义时修复格式；不要求按字符宽度对齐表格，不重新排列行列。
8. **中英文与标点**：正文中非公式的括号统一使用中文全角括号 `（` 和 `）`，括号外侧与相邻正文或标点之间不留空格。若左括号紧跟列表标记，必须保留标记与括号之间的空格，例如 `- （内容）`，以确保 Markdown 将其识别为列表项。非公式中的说明性冒号使用中文全角冒号 `：`。正文引号使用英文双引号 `"`，引号外侧与相邻正文之间各留一个空格；位于段首、段尾或紧邻其他标点时不额外插入空格。代码、公式、路径和其他有固定语法的内容保持原样。英文字符、英文单词和缩写与相邻中文正文之间各留一个空格；句首、句尾或紧邻标点时不额外插入空格。正文中的文件名、文件扩展名，以及表示寄存器或代码变量的英文标识符使用行内代码反引号包裹，并按上述规则与相邻中文正文留空格。保留代码块、已有行内代码、公式、链接、路径、URL、型号及其他有固定语法或写法的内容；不转换其中的括号或冒号，不在其中插入空格。对标识符的含义或标点用途无法确定时，保留原文并报告。

## 执行与验证

1. 确认用户指定的目标和适用的更深层指令，读取相关文档并识别代码块、公式、列表、引用、表格和链接等结构。默认检查 `.md` 文件；对于疑似 Markdown 但扩展名异常的文件，只报告，不自动重命名或纳入修改，除非用户明确指定。
2. 对符合上述规则且可确定安全的格式问题直接修复；仅改动必要内容。发现疑似笔误时，保留原文并列出文件、位置及建议修改，询问用户是否修改；用户已授权修改的笔误可直接修正。遇到其他歧义、缺失资源或需要技术判断的问题，保留原样并记录文件与行号。
3. 检查修改前后的差异及相关 Markdown 结构；对修改过的本地链接或图片路径验证目标存在。使用仓库已有的合适检查工具时，注意它对公式及嵌套结构的支持；不要为审查而安装新依赖。若无法验证某项，明确说明。
4. 最终报告列出已修改的文件、主要修复类型和验证结果；列出未自动修复的问题及原因。若没有需要修改的内容，也明确说明。
